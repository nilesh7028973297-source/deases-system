Features

🚨 Health alerts

Warnings for fever, low SpO₂, abnormal heart rate, high blood pressure and glucose.

📧 Email summary

A prediction summary is sent after each session through Flask-Mail and Gmail SMTP.

👤 User profile

Edit name, email and picture. See total predictions, top disease and feedback accuracy.

💬 Live chat board

A shared message board for users, refreshed every 2 seconds.

📡 Sensor integration

Temperature, heart rate, SpO₂, blood pressure and glucose through serial or BLE (pyserial, bleak).

📅 Prediction history

Every prediction and sensor reading is stored in MySQL, with correct/wrong feedback.

✅ Dataset validation

Checks missing values, duplicates, binary features and class balance before training.

🧪 Robustness testing

Accuracy under symptom noise and dropped symptoms, plus the confusion matrix.

🔍 Explainability

Shows which selected symptoms influenced the prediction most.

Architecture

User→Frontend→Flask app→Input validation→ML model→Result + alerts→MySQL history

Sensors (serial/BLE) → live acquisition → vitals mapped to symptom features → model

Limitations

Prediction quality depends on the dataset. Symptoms overlap across diseases, user input may be inaccurate, and the model hasn’t been clinically validated. Sensor readings need a model designed for those inputs. This system is for education only, not for diagnosis.
